# PR-1H — Known Deferred Limitations

Documented, not fixed in this phase, per the explicit scope boundary.

| # | Limitation | Status / Why deferred |
|---|---|---|
| 1 | Final Login V3 design (`/login-v3` cutover) | Explicitly deferred to the end of the roadmap per current production policy. `/login` remains on Login V2. Not touched in PR-1H. |
| 2 | Passkey/WebAuthn | Not started. The Face ID / Passkey buttons on `/login` are inert, disabled UI placeholders only (`disabled`, `aria-disabled="true"`, click handlers call `e.preventDefault()`) — no backend, no `navigator.credentials` call anywhere in the codebase. Confirmed unchanged in PR-1H. |
| 3 | Physical-device certification gaps | Carried forward from PR-1E — all responsive/mobile certification across this program has used Chromium viewport emulation only, never real iOS/Android hardware. |
| 4 | Live multi-role production-testing gaps | This phase's certification was code-level plus a single live, unauthenticated browser session against the dev server (route guards, login rendering, responsive layout). No real login was performed for any of the 7 roles against production Firebase Auth during PR-1H, since doing so would require real credentials this audit does not have and should not create. |
| 5 | Official Firestore export backup | Still not verified — PR-1G-B0 confirmed the backup procedure is ready but blocked on Google Cloud billing being disabled on the `pharmapulse-646de` project. Unrelated to and unresolved by PR-1H; current policy explicitly forbids enabling billing in this phase. |
| 6 | Production data reset | Not started, not authorized in this phase. PR-1G-A's reset proposal remains pending owner approval; current policy explicitly forbids it in PR-1H. |
| 7 | Git-history scrub (old `.env` values in history) | Identified in PR-1G-B0's secret rotation checklist; not performed — requires `git filter-repo` or equivalent, a separate, explicit owner-approved action with its own risk profile (rewriting shared history). |
| 8 | Staging environment | None exists. Confirmed in PR-1G-A that the codebase has no code-level mechanism to distinguish a staging Firebase project from production — there is only one project. Out of scope for a stabilization phase; would require new infrastructure. |
| 9 | Optional dead-code cleanup | `src/data/dummyData.js` (hardcoded test credentials, confirmed unimported/dead in PR-1G-A) was flagged again during PR-1H's hygiene sweep but not deleted — deleting dead code was explicitly out of this phase's "fix only confirmed defects" bug policy; recommended for a future cleanup pass. |
| 10 | Preview asset cleanup | `/login-v3`, `/login-concept-a/b/c`, `/login-network-preview`, `/login-vortex-preview` and their asset folders remain in the codebase, reachable by direct URL, unlinked from any production nav (confirmed via Sidebar.jsx/MobileNav.jsx audit and a live check that `/login-v3` loads in isolation without affecting `/login`). Removal was explicitly out of scope this phase ("if direct production exposure creates a real risk, gate ... without deleting source files" — no real risk was found beyond the already-accepted unlinked-but-reachable state from PR-1G-A, so no gating action was taken either). |
| 11 | Broad UI redesign | Not performed — this phase is explicitly stabilization-only, not a design phase. |
| 12 | New AI features | Not performed — out of scope. |
| 13 | Evaluation methodology review (weight redistribution on missing optional KPI; explicit 2-decimal score rounding) | **RESOLVED in PR-1I** (dedicated compliance phase, all new + existing tests passing — see [`PR1I_EVALUATION_COMPLIANCE.md`](PR1I_EVALUATION_COMPLIANCE.md) and [`PR1I_RELEASE_DECISION.md`](PR1I_RELEASE_DECISION.md)). Originally surfaced during PR-1H certification (see [`PR1H_BUG_REGISTER.md`](PR1H_BUG_REGISTER.md) "Findings deferred, not fixed"); both required a dedicated, product-owner-approved methodology phase rather than a stabilization bug fix, which PR-1I provided. |
| 14 | `VITE_DEMO_MODE` Netlify env var is a no-op | Confirmed again in PR-1H — configured in `netlify.toml` per-context but read nowhere in `src/`. Not a security issue, just unresolved configuration hygiene from PR-1G-A; left as-is since fixing it would mean either writing new feature-gating code or changing deploy config, both outside a stabilization-only bug-fix policy. |
| 15 | Reports' internal export vs. Export Studio — two independent export paths | `ReportsPage.jsx` builds its own CSV/Excel/Report-Pack exports inline rather than delegating to the shared Export Studio dataset builders. This is a design observation, not a defect — both paths were independently certified clean (no raw IDs, no secrets, no CLAIMED leakage) in PR-1H. Consolidating them into one shared export pipeline would be a refactor, explicitly out of scope for this phase. |
